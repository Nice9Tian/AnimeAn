## 待用户项

- 真机点击（2026-11-14 用户让用 computer-use 在真机上测，main ea5e268 的 dist）：
  - 点被禁用的主窗口：什么也不发生，前台仍是对话框。成立。
  - 点浮出的面板窗口：点击被页面挡住了，但面板窗口拿到了前台，排到对话框上面（z 序面板在前），对话框没有被提到最前。原因：真实点击让 WebView2 给面板设了焦点，不能激活的窗口也被激活了；`focus_modal` 激活的是主窗口最后激活的弹出窗口，这时就是面板。隐藏桌面上发的是 DevTools 的鼠标事件，WebView2 不设焦点，所以没测出来。2026-11-14 已修（用户让直接修）：`focus_modal` 改为按 z 序找本程序里归主窗口所有、显示着、没被禁用的最上面那个窗口，面板除外，即上层对话框或系统选择框。
  - 主窗口最小化时弹出的对话框落在显示器正中，还原后在主窗口之上、主窗口仍锁着。成立。
- 同时开两个 AnimeAn 时（共用一份 WebView2 配置）会串台。2026-11-14 真机复现，同日已修（用户让直接修）：每次运行起一个名字，主窗口页存进 sessionStorage，开面板窗口和对话框窗口时放进网址（`relay=`），中转和「对话框已显示」的频道都带上这个名字。修之前的情况：面板窗口和对话框页经 `relay.ts` 的 BroadcastChannel 找主窗口页，频道名是固定的，两个实例的页面在同一个频道上：
  - 一个实例的面板和对话框发的调用，两个实例的主窗口页都会转给自己的后端；
  - 一个实例关掉时它的页面发 `bye`，另一个实例的对话框页和面板页就当自己的主窗口断了，此后的调用都被拒（「主窗口未连接」）。开着的模态对话框再也关不掉，主窗口锁着，也关不了窗口，只能结束进程。
- 菜单画在主窗口页里，浮出的面板窗口会盖住菜单，被盖住的项看不见也点不到（真机上 Windows 菜单下半截被 Layers 面板盖住）。早就有，2026-11-14 已修，见 `../plan/2026-11-14-菜单不被面板挡住.md`。
- File、Edit、Theme、Windows 菜单的项已经归 Python（#112）。
- `../user-workflow.md` 第 18 行末句「Draw、Arrow、Auto Mapping 三个菜单由脚本提供」已删掉（用户 2026-11-14 授权改一级文档；现在菜单栏的菜单都由脚本提供，细节在 `../mechanism/hook_events.md`「菜单栏」）。
