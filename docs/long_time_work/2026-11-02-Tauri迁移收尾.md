## 〔裁〕清单

都在 `../mechanism/windows_theme.md`「窗口层级」和「纹理板的单一所有权」，`../product_features.md` 第 13 行已标。D3 的承诺是浮动面板变独立窗口，下面三处没有做到跨窗口：

- 纹理子控件框留在主窗口内浮动。它所在的面板变成独立窗口时，框在主窗口里浮出来，那个面板显示 `Texture is in the main window`。跨窗口要在别的页面重建画板和 WebGL 上下文，后端的 `child` 只有一路帧流。
- 独立窗口拖回主窗口不会自动停靠，用浮动按钮或双击标题恢复。Windows 系统拖动窗口时网页收不到坐标。
- Assets 拖到 Layers 不跨窗口。两边是不同页面。

## 只汇报、不修

- `JsonVariant::toInt` 截断：现有调用走不到。
- 气泡文字不支持基本多文种平面以外的字（emoji 等）：GDI 路径按 UTF-16 单元取字形。
- `Timer` 的到期按循环开始时刻算，不是调用时刻：差一个循环。
- `initializePythonStartup` 在 `initalize.py` 之后才 `resetHistory`，和 Qt 相反。Python 启动阶段写的历史被清空，且多两次 `historyrestore`。行为上没发现影响。
- `palette_box` 的默认色板跟随当前颜色，所以文档还没有存过色板时，New Color 第一次 Add 是空操作（颜色已经在默认表里），下次再 Add 就把上一个顶掉了。Qt 版同样如此，`pyfile/` 不动，只记录。
- 从独立窗口触发的设置窗出现在主窗口，和 Qt 一样是主窗口的模态框。独立窗口盖在主窗口中间时要挪开才看得到。

## 验收之后的修复

- 撤销、重做和 History 跳转落到主画板时切回 Drawing 页（#86）。原来列在只汇报里：`user-workflow.md` 写的是切过去，Qt 和网页都只切了纹理板一侧。用户交给 Agent 定，按「语义高于代码」改代码。
- 从 Texture 页 Open 工程也切回 Drawing 页（#86）。Qt 本来就切，迁移时漏了。根因相同，都是活动板换到主画板时页面没跟上。新旧对比的基线是无界面会话，这类只在 `MainWindow` 里的行为比不出来。`mainwindow.cpp` 里切页的调用点都对过一遍，这是唯一漏掉的。
- 相对修复前的新旧对比：26 个场景、497 步，10 处差异，都在 `history_and_alternating_views` 落到主画板的四步，都是 `paint` 的当前页和 `window.select`。画板内容没有差异。
- `ui.windows` 的 `paint` 当前页改成按焦点算，用户定：焦点所在的板，焦点不在板上时算最后拿到焦点的那块，也就是活动板（#87）。原来存的是中央页，开着纹理框时会和焦点对不上。网页补上 Qt 的另一半：板子成为活动板时把键盘焦点交给它，切页签、开纹理框、撤销切板后蓝框都在活动板上，原来是灰框。相对 #86 的新旧对比 5 处差异：无界面会话没有页面报纹理板的家，`window.select` 不再发（真实页面照发）；`windows` 状态在两步里一次少发、一次多发，值都和活动板一致。
