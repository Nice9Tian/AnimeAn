# Linux 开发环境（2026-11-17）

状态：已完成，回填在文末。机制（三级）：`../mechanism/platform.md`、`../mechanism/build_deploy.md`「在 Linux 上开发」。

## 目标

用户 2026-11-17：以后打算在 Ubuntu 上继续开发这个软件；还是面向 Windows 用户，不是抛弃 Windows。

所以要做到：

1. 代码在 Linux 上编得过、跑得起来，自动测试在 Linux 上能全跑。
2. Windows 上的行为一点不变，发布包仍是 Windows 的 `dist\AnimeAn\`。
3. 在 Linux 上改完代码，不回 Windows 机器也能知道 Windows 上还编不编得过。

不做：Linux 发布包；把产品写成跨平台的。`../product_purpose.md` 写的「Windows 桌面」不动，这次没有改一级和二级文档。

## 已定决策

用户定的只有上面那句话。下面是 Agent 施工时定的，用户可以推翻：

| 决定 | 理由 |
|---|---|
| 系统调用抽成薄层，每层一份 Windows 实现、一份 Linux 实现，上层逻辑只留一份 | 原来的 `algorithm/core/file.cpp` 里非 Windows 分支全是空实现，事件循环和 WebSocket 服务端直接写 Winsock；逐处加 `#ifdef` 会让每个文件都背着两个系统 |
| Windows 的系统调用代码原样搬进新文件，不改写法 | 发布的是 Windows 版，这次不该让它有行为变化；搬完用和真实 Qt 的差分测试、新旧录制对比核对 |
| 路径文字的读法不分系统（两种斜杠、盘符、UNC 在 Linux 上照认） | Windows 上写的工程拿到 Linux 上打开，相对路径意思不变；也不必让上层逻辑分系统 |
| Linux 上界面字体先找 Windows 那三种，没有再用 Noto / DejaVu | 装了同样字体的机器上文字和 Windows 一致；没装也有字可用 |
| Linux 的运行时用环境变量 `ANIMEAN_PYTHON_HOME` 指，不放进 checkout | `tools/python312` 是 Windows 的运行时；Linux 上一份只读的共享运行时可以给所有 checkout 和 worktree 用 |
| Linux 的 wheel 不入库 | 没有 Linux 发布包，入库只会让公开仓库多二十来兆；开发机的运行时按 `requirements.txt` 从 PyPI 装同样的版本 |
| Windows 上还编不编得过，用 MinGW-w64 交叉编译来查 | 发布用的就是 MinGW，交叉编译用同一族编译器；只查编译和链接，不运行 |
| Node 脚本启动后端的环境收成一个模块 `build_scripts/backend_env.mjs` | 原来七个文件各写一遍，写死了开发机上的目录，在别的机器和系统上都不对 |
| 外壳在 Linux 上只求能编、能起后端、能开窗口 | 对话框模态和菜单挖洞靠窗口句柄，是 Windows 的做法；Linux 上手测界面走浏览器连后端 |

## 施工顺序

1. `algorithm/core`：`native.h` 一层（文件、目录、进程、环境变量），`file.cpp` 拆成 `file.cpp` + `fileinfo.cpp` + 两份系统实现，`settings.cpp` 不再含系统头文件。
2. `backend/platform`：`sockets.*`、`process.*`；`eventloop.cpp` 和 `backend/net/wsserver.cpp` 改用它们。
3. `backend/board`：`textpath.cpp` 留排版和缓存，字形分到 `textglyphs_gdi.cpp` / `textglyphs_freetype.cpp`。
4. `pythonbind/python_environment.*`：后端和 `board_headless_test` 原来各写一份的 Python 环境合成一份。
5. CMake 按系统选源文件和链接库；Python 版本号只写一处。
6. 测试脚本：`t_*.py` 的路径拼接、Node 脚本的启动环境。
7. `src-tauri`：只在 Windows 上要的依赖和代码加条件；补 Linux 的退出监视和随外壳退出。
8. Linux 构建脚本、交叉编译检查、文档。

## 风险

- **Windows 行为被改动**：文件层是整个重排。对策：`core_file`、`core_settings` 差分测试、新增的 `fileio` 测试、Windows 上新旧录制对比。
- **两个系统的隐含差别**：文本模式换行、隐藏文件、`int64_t` 的底层类型、`SIGPIPE`、端口复用。都写进了 `../mechanism/platform.md`。
- **Linux 上测不到的东西**：外壳的窗口行为、`tests/ui_pixel/`、发布包。这些仍要 Windows 机器。

顺手改掉的：

- `JsonValue` 多了 `long` 的构造函数，`Settings` 的整数接口从 `std::int64_t` 改成 `long long`（Windows 上是同一个类型）。
- `Dir::cleanPath` 里一个赋了值但没人读的局部变量删了。
- `backend/tests/golden/record.mjs` 每次运行把自己目录下的源码改写成 CRLF，这一步只在 Windows 上做了。
- `mechanism/build_deploy.md` 里会话冒烟的路径少了一级 `backend\`，改对了。

### 测试结果（2026-11-17）

|---|---|
| Windows（MinGW 13.1，worktree 的 `build\wt-check`） | `ctest` 17 项全过，含和真实 Qt 6.9.1 对比的 `core_file`、`core_settings` 和新增的 `fileio`；新旧录制对比（改动前的 `build\Release` 对改动后）`GOLDEN_SAME scenarios=25 steps=488` |

### 须知

- 新旧录制对比不能跨系统比（字体不同）。
- Linux 上外壳的对话框模态和菜单挖洞没有实现。
- 交叉编译出来的 `AnimeAnBackend.exe` 没有在 Windows 上运行过，它只用来查编译和链接。
