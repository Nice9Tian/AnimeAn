## 已定决策（用户）

- 二级承诺（已批，原样写进 `../product_features.md`）：对话框是独立窗口，弹出时在 AnimeAn 所有窗口之上（不盖住别的软件）；对话框开着时，其它 AnimeAn 窗口不能操作，点它们会把对话框提到最前。
- 对话框挂在主窗口下，不用系统级的始终置顶，切到别的软件时跟着退到后面。
- Python 持有「模态中」这个状态，决定弹什么、是否模态。C++ 只提供开窗口、广播状态、出错兜底（窗口被关或出错时一定清掉状态）这些通用函数。网页只负责画。
- 网页现在自己弹的对话框和自己加的菜单项都算偏离，改成经 Python 发起：文件出错提示、覆盖确认、Canvas Size、New Color、Settings 菜单里的项。
- 一级规则：`../developer_guide.md`「分工」第二条（#104）。

## 现状（main cb5e0af）

- 对话框都画在主窗口页面里（`.qdialog-shade` 盖住页面）：New Project / Canvas Size（`webui/src/ui/panels2.js` 的 `createNewProjectDialog`，启动时由网页自己弹）、`messageBox`（文件出错、覆盖确认、导入时问要不要缩放到画布）、New Color（`app.js` 的 `openNewColor`）、选项里颜色控件的取色框（`options.js` 的 `openColorDialog`）、脚本设置窗（`app.js` 的 `openSettings`，C++ 发 `settings.open`）。
- 文件流程在网页：C++ 收到 File 菜单只发 `dialog.openProject`、`dialog.saveProjectAs`、`dialog.canvasSize`、`menu.action` 事件，弹哪个原生选择框、先探测再问覆盖、导入时问缩放、失败时弹错误框，都由网页决定。
- Settings 菜单（Board Renderer、Language）是网页自己拼在菜单栏末尾的。
- 独立面板窗口挂在主窗口下；对话框只画在主窗口里，面板窗口盖在主窗口中间时挡住它。

## 设计

各层之间只传声明：

| 层 | 做什么 | 不做什么 |
|---|---|---|
| Python `pyfile/dialogs.py` | 对话框栈：谁开着、谁在最上、是否模态；每个对话框的结果回调；把栈经 `ui.set_dialogs` 交给 C++；处理网页发来的 `dialog` 事件（结果、请求）；通用请求（颜色控件取色、脚本设置窗） | 不画 |
| Python `pyfile/file_menu.py`、`pyfile/ui_settings.py`、`pyfile/palette_box.py` | File 菜单流程（选择框 → 探测 → 覆盖确认 → 执行 → 出错提示）、启动时的 Canvas Size、Settings 菜单（渲染器、语言）、New Color | — |
| C++ | 通用函数：`ui.set_dialogs`（存下、广播 `dialogs` 状态）、`ui.broadcast`（Python 自己的状态，键以 `py/` 开头）、`ui.state`（读一份状态）、`ui.call`（调一个后端方法）；`dialog.result`、`dialog.request` 两个调用转成 Python 的 `dialog` 事件。兜底：窗口被关、页面出错、Python 处理时抛错，都从 `dialogs` 里清掉这一条并记下它的 id，Python 再发旧栈也带不回来 | 不认识任何一种对话框 |
| 外壳 | 通用函数：开对话框窗口（无边框、挂在指定窗口下、不进任务栏）、按内容定大小并居中显示、关窗口、禁用 / 启用一个窗口、让一个窗口不能被激活、把输入交给当前模态的窗口；用户关掉对话框窗口时告诉主窗口 | 不决定开哪个 |
| 网页 | 主窗口页按 `dialogs` 状态开关对话框窗口和原生选择框，按模态锁住其它窗口；对话框页（`dialog.html`）按声明画，把按钮和取值发回；模态时每一页都挡住输入，点一下把对话框提到最前 | 不决定弹什么 |

窗口层级：第一个对话框挂在主窗口下，嵌套的（设置窗里点颜色）挂在下面那个对话框下，所以总在它上面。模态时外壳禁用它的所有者（主窗口或下层对话框），这是 Windows 的标准模态：点被禁用的所有者，系统把最后激活的弹出窗口提到最前。独立面板窗口和对话框同是主窗口的所属窗口，模态时设为不能激活（点它们不会升到对话框上面），页面挡住输入，点一下把对话框提到最前。关对话框前先启用所有者，否则系统会把焦点交给别的软件。原生文件选择框由系统禁用主窗口，外壳不再另外禁用。

对话框的种类（`kind`）：`message`（标题、正文、按钮）、`canvasSize`（宽高与预设）、`color`（取色，确认按钮的字由 Python 给）、`settings`（脚本设置窗，控件和选项面板同一套）、`file`（原生选择框）。文字都是英文原文，网页显示时翻译。

## 风险

- 点被禁用的主窗口时，系统会不会把对话框提到最前：这是 Windows 模态框的标准行为，但隐藏桌面上发不了真实鼠标输入，只能查窗口状态（所有者、启用、z 序、焦点）和页面里的点击。真机点击记为待用户项。
- 原生选择框关闭时自己会启用主窗口，和外壳的禁用打架：这一种不由外壳禁用主窗口。
- 重入：Python 处理对话框结果时经 `ui.call` 调后端方法，后端方法里又会调 Python。和现在网页调这些方法走的是同一条路，冒烟覆盖保存、打开、导入。
- 卡死在模态：任一层出错都必须能解锁。C++ 兜底清状态；网页在后端断开时关掉对话框窗口并解锁；外壳在主窗口关闭时带走对话框窗口。
- 测试工具依赖旧事件（`settings.open`、`dialog.*`）：会话冒烟、`i18n_coverage.mjs`、网页测试一起改。
- 启动的 Canvas Size 由 Python 在启动后放进 `dialogs`，没有网页连着时它也在；只读后端状态的测试工具会看到它。
