# 代理矩形对齐（issue #9，父 issue #7）

状态：**已完成**（算法与回归）。界面和曲面接入不在本计划内，见「留给其他 issue」。规格（一级）：`../../auto_mapping/proxy_rect.md`。

## 目标

纹理板上有一个矩形，用户在主画板画一个矩形，算出哪个角对哪个角，再由此算出主画板的 H/V 轴线和额外辅助线。纹理板的轴线是已有的，不计算。

## 已定决策（用户 2026-10-30）

1. 根据主画板的矩形立刻算出 H/V 轴线和额外辅助线（或还没做的 Coons 曲面）。纹理板的矩形只示意映射范围，图案和轴线都不随它动（用户试测试台时纠正）。
2. 不计算镜像：只有绕到背面才需要镜像。
3. λ = 1.0，平移和缩放的代价为 0。
4. 每次改动都重算，不存状态；矩形转过临界角时图案会换标签，用户知情。

## 拍板前的实测

两个脚本在本目录，跑法 `py docs\plan\2026-10-30-代理矩形对齐\surface_compare.py`，从仓库根目录运行。

**对齐结果能不能当初始形态（`surface_compare.py`）。** A 是主画板轴线取四边形中线，B 是轴线取对齐后矩形的轴线。都走真实的 `build_mapper`，边界残差用均匀拉普拉斯场吸收。表中是折叠格数。

| 样本 | A，轴钉住 | B，轴钉住 | B，轴放开 |
|---|---|---|---:|
| 300×200 → 200×300 | 0 | 114 | 0 |
| 轻度梯形 | 0 | 2 | 0 |
| 强梯形 | 0 | 10 | 0 |
| 一般凸四边形 | 0 | 51 | 0 |
| 大位移 + 梯形 + 旋转 | 0 | 6 | 0 |

- 轴放开时 A 和 B 都等于双线性 Coons 曲面（偏差不超过 $1.1\times10^{-9}$ px），调和场的解由边界唯一决定。
- 轴钉住时 A 也等于双线性 Coons 曲面（不超过 $5.9\times10^{-10}$ px），因为残差 $d\,uv$ 调和且在轴上为零。
- 所以 B 不是和 A 一样，就是比 A 差。用户据此选了由主画板矩形直接算轴线。
- 边鼓起 8% 时轴钉住有约 24 px 的折痕，放开时 0.02 px；一般四边形钉轴时 A 折 1 格、B 折 14 格。

局限：场是均匀拉普拉斯，不是 `_FlowFieldWarp`；主画板轴线都是直线。

**四条边当附加线能贴多近（`edges_flow.py`，真实流场）。** 边上离目标的偏差，单位 px。

| 样本 | 只有轴线：均值 / 最大 | 加四条边：均值 / 最大 | 折叠 |
|---|---:|---:|---:|
| 轻度梯形 | 7.80 / 15.00 | 4.02 / 8.58 | 0 |
| 强梯形 | 39.00 / 75.00 | 24.02 / 58.41 | 0 |
| 一般凸四边形 | 15.16 / 29.15 | 6.95 / 12.66 | 0 |

相似变换和长宽比变化本身的残差是 0。附加线大约减半，到不了轮廓，符合「附加线只引导流向」。

2. `tests/t_proxy_rect.py`：十五项。

## 风险

- 用户选了每次重算，矩形转过临界角时图案会跳，表在规格页 §4。逐帧轴线落地时再看要不要改参考。
- λ = 1.0 时长宽比差很多的矩形会被压得很厉害，只能靠用户改画法。

## 留给其他 issue

- **#8**：直边时 Coons 不用放弃，现有 `hv` 加调和残差就是双线性 Coons，要在 `_FlowFieldWarp` 上确认。同日的 Coons 必要性评估（目录 `2026-10-30-issue7-Coons必要性评估`）独立得到相同结论，也认为 #9 只定四角对应；它建议弯边时用 Coons 中线当轴，`guides` 现在按双线性把纹理轴线带过去，弯边接入时要换成 Coons。
- **#10**：矩形工具给四个角和四条边，`guides` 目前只吃角点，手绘的弯边要加进来。纹理板上的矩形从哪来（用户说「原本有一个」）也在这里定。
- **#11、#12**：边弯时不能钉轴；轮廓要位置约束，附加线不够。
