## 目标

- 网页界面能完全替换 Qt 界面。
- 改界面和 Python 不用编译。改 C++ 只重编后端。
- 手感以 WebView2 为准，桌面和浏览器走同一条输入和绘制路径。
- Auto Mapping 的算法、`pyfile/` 的功能层、工程文件格式都不变。
- 仍是 Windows 桌面软件，仍是解压即用、离线可运行的压缩包。

## 最终目标与硬约束

最终目标：网页版能完全替换 Qt 版，`pyfile/` 不用改。

**验收：** 合并时 `git diff $(git merge-base main HEAD) HEAD -- pyfile/ pythonbind/animemodel.py opentoonz_tools/` 为空，`tests/t_*.py` 全过。为了合并而不得不改 Python 的地方，算迁移的缺陷，要改后端，不改 Python。

这条只管迁移分支自己的提交。PR #20 合入后功能开发回到 `main`，`main` 上的 `pyfile/` 会继续变，直接和 `main` 比会把新功能算成迁移缺陷，所以 2026-11-02 改成和 merge-base 比（用户授权）。迁移分支合并 `main` 时会带上这些改动，merge-base 跟着前移，这不算迁移改 Python。

**PR #51 带来的新依赖：** 覆盖层多了 `label` 字段，气泡文字用 `QPainter::drawText` 经录制层转成路径，靠 Qt 的字体。第 5 步后端完全去 Qt 时要给它换实现：网页端画文字，或者另找字形来源。Python 这边发的还是 `ui.set_overlay` 的项，不用改。

这条能成立，是因为 Python 看到的 C++ 接口可以保持不变：

| Python 用到的接口 | 规模 | 迁移后 |
|---|---|---|
| 模型：`SceneModel`、`VectorImage` 等 | 绑定 115 个，Python 用到约 86 个 | 内部改用纯 C++ 类型，名字和行为不变 |
| 几何：`vectorlogic`、`model_pybind` | 绑定 32 个 | 同上 |
| 界面门面 `ui` | 绑定 25 个，几乎都是单向通知 | 名字不变；现有回调槽换一组实现，转发给网页。查询类（主题、窗口列表）由后端缓存作答 |
| 钩子事件 `python_hooks.dispatch` | 40 处派发，`openglwidget.cpp` 里 141 行写消息字段 | 画板引擎组出**字段完全相同**的消息 |
| 菜单、设置窗、选项面板 | Python 返回 JSON，控件类型有 list、slider、check、button、color、subwindow、palette 等 | 网页按同一份 JSON 渲染 |

Python 仍然嵌在后端进程里，所以 `pydeps` 的 pip 自装、To 3D 的 `os.startfile` 都照常工作。Python 同步调用 `ui.*` 时不用等网页回复，界面通知异步发出，这也让网页不会被长计算卡死。

钩子消息是最容易悄悄走样的接口。第 5 步用录制比对来守住它：在 Qt 版上录下一批交互事件产生的消息序列，在新引擎上回放同样的输入，逐字段比较。

## 并行开发与合并

迁移在分支 `claude/tauri-migration` 上做，和代理图形（issue #7 及 #8–#12）并行，找合适的时机合并。Qt 文件可以改。

- **定期把 `main` 合进分支。** 这样 `mainwindow.*`、`openglwidget.*`、`algorithm/` 的冲突不会积压到最后。
- **盯住接口变化。** `main` 上新增的绑定、`ui` 函数、钩子消息字段或控件类型，每次同步时都要在后端和网页补上。#10（代理矩形的输入工具）如果新增 Qt 工具，就属于这一类。
- **分支上 Qt 版一直能编译。** 它是录制比对的基准，合并切换时才移除。

## 架构

```text
网页界面 + 画板渲染端（WebGL）
  运行层来自 VibeFrontend（webui/vf），面板在 webui/src/ui
  ├─ tauri dev / 正式包：跑在 WebView2 里，浮动面板是独立窗口
  └─ 浏览器调试：跑在 Chromium 里
        │ 本地连接：输入、事件 ↓   状态、绘制列表 ↑
        ▼
旁路后端进程
  业务层 + 画板引擎 + 纯 C++ 计算层 + 嵌入式 Python（pyfile/）
```

开发时改动的代价：

| 改什么 | 要做什么 | 大约多久 |
|---|---|---|
| 界面、布局、交互逻辑 | 页面自动刷新 | 不用编译 |
| Python | 后端热重载 | 不到 1 秒（待实现） |
| C++ 后端 | 只重编后端，页面不关 | 5–12 秒（现有桌面版实测） |

## WebGL 画板

2026-11-01，用户要求完成 WebGL 版画板，并在设置里加切换选项。机制见 `../../mechanism/backend_protocol.md` 的「渲染器」。

`webui/src/board/glrenderer.ts`、`tess.ts` 用 WebGL2 回放同一份指令表，缺省使用，不支持时退回 Canvas 2D。切换在 Settings ▸ Board Renderer，Qt 版没有这个菜单。

| 项目（1280×720，3000 条笔画，每条 40 段三次曲线，RTX 3080） | 结果 |
|---|---|
| Canvas 2D 全量重画 | 约 600 ms |
| WebGL，几何缓存命中 | 4–12 ms |
| WebGL，换缩放档重建几何 | 260–360 ms |
| 和 Canvas 2D 逐像素比较（单通道差不超过 24） | 99.92%，增量 6 帧 99.92–99.99% |

- 这里的 Canvas 2D 比「实测依据」的 133–152 ms 慢，因为这次测量强制等绘制完成，场景也不同。
- 密集细线比 Canvas 2D 淡：解析抗锯齿的边缘叠加时累积变深，多重采样按实际覆盖计算。稀疏时各线宽的墨量比在 0.92–1.06 之间。
- 一帧的几何超过 128M 个浮点数时，每帧都要重建，退化到接近 Canvas 2D 的速度。

## 计算层去 Qt

2026-11-01，用户要求组织一批 Argon 并行完成，每个工作包一个 PR。

**做法：** 新建不依赖 Qt 的类型层 `algorithm/core`（规则见 `../../../algorithm/core/README.md`），方法名和 Qt 相同，隐式共享。计算层批量换类型，Qt 程序和后端在边界上隐式转换（`qtbridge.h`）。路径布尔运算用 Clipper2，PNG 用 stb，都放在 `external/`，用户已确认。

**完成标志：** `animean_core` 没有 Qt 的包含路径，也没有 Qt 的未定义符号。

**验证：**

## 风险

- **真笔未测。** 第 0 步就是为了尽早发现这个问题。
- **计算层去 Qt 改变结果。** 已逐例比较：填充边界由 Clipper2 算出，元素序列和 Qt 不同，区域在容差内；其余结果逐位相同。
- **长期分支的冲突。** `mainwindow.*`、`openglwidget.*`、`algorithm/` 两边都会改，不定期同步，最后的合并会很难。
- **接口悄悄走样。** 钩子消息少一个字段，Python 不一定报错，只是行为变了。要靠录制比对发现。
- **手感要重新调。** 输入路径变了，稳定器和拟合参数可能要调。这些参数改动是三级；Auto Mapping 的常量仍是一级。
- **画板引擎难拆。** `openglwidget.cpp` 有 4424 行，界面和逻辑混在一起，估算的不确定性最大。
- **独立窗口。** 纹理板不跨窗口搬迁，是这次的〔裁〕之一：它所在的面板变成独立窗口时，框留在主窗口里浮着。
- **低端显卡没有数据。** 全部绘制数字来自 RTX 3080。
- **绘制结果不会逐像素相同。** WebGL 和 QPainter 的抗锯齿不同，笔画形状以后端的路径为准。
- **WebView2 自动更新。** 引擎版本由系统更新，发布时要确认是否随包固定版本。
