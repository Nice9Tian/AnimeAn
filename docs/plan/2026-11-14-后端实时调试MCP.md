# Chrome 联调与跨 Agent 后端实时调试 MCP（2026-11-14）

> 目标：在不改动 `backend/`、`pyfile/`、`webui/`、`src-tauri/` 任何产品运行时的前提下，为 Chrome 手测绘画流程提供一套跨 Agent（Antigravity、Claude Code、Codex、Cursor、Gemini CLI、Streamable HTTP）可用的后端实时调试 MCP 工具链。

相关机制说明见 [../mechanism/mcp_backend_debug.md](../mechanism/mcp_backend_debug.md)。

---

## 1. 背景与决策记录

1. **为什么建在独立脚本层 `tools/mcp-backend-debug/`，而不把 MCP 塞进 C++ `AnimeAnBackend.exe`？**
   - 保持产品后端、Python 运行时与前端完全零侵入，不需要重编 C++/Rust，也不会把测试依赖带入发布包。
   - 后端一旦崩溃或重启，独立 MCP 进程可存活并重连，同时还能通过 `backend_launch_dev` / `dev_chrome.ps1` 管理后端与 Vite 的启动。
2. **为什么选被动多端 WebSocket + 带外文件 IPC 的组合？**
   - 浏览器测试期间 Chrome 必须保持对 `m_presenter` 与 `fieldDisplaySupported` 的所有权，因此 MCP 观察客户端绝不发送 `input`、`texture.setHome` 或 `board.capabilities`，在没有浏览器接入前巡检后会主动释放连接。
   - 几何控制点与 `scriptData` 体积大，若直接 `print` 回 `python.run` 会冲毁 2000 条上限的 `window.pythonDebug`；文件 IPC 只向 `pythonDebug` 写一行 `[mcp_probe] ok:<op>`。
3. **为什么做双帧 Stdio + Streamable HTTP？**
   - Claude Code / Codex / Cursor 使用 NDJSON stdio，部分 LSP/扩展客户端使用 `Content-Length` 帧头，`--http` 兼顾远程或本地 HTTP MCP 客户端，统一复用同一个核心 `ToolRegistry` 与 `createMcpHandler`。
4. **为什么将调试会话文件写到 `<gitCommonDir>`？**
   - 主仓库与多个 `git worktree` 并存时，Agent 在任一 worktree 都能自动发现当前 Chrome 正在使用的 `AnimeAnBackend.exe` 端口与令牌。

## 2. 交付清单

- 嵌入 Python 只读探针：`tools/mcp-backend-debug/python/_mcp_probe.py`
- MCP 核心与 14 个工具：`tools/mcp-backend-debug/src/`、`tools/mcp-backend-debug/mcp_server.mjs`
- Chrome 一键启动与配置导出：`tools/mcp-backend-debug/cli.mjs`、根目录 `dev_chrome.ps1`
- 多 Agent 接入清单与 Antigravity 插件：`.mcp.json`、`.agents/plugins/animean-backend-debug/`
- 自动化测试：`tools/mcp-backend-debug/tests/unit.test.mjs`、`tools/mcp-backend-debug/tests/integration.test.mjs`
- 文档：工具说明（位于 `tools/mcp-backend-debug/`）、机制文档与本计划文档
