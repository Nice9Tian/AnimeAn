# 菜单项归 Python

用户 2026-11-03 在对话框窗口那个会话里定下要做，并让在那个会话里直接做：主窗口的 File、Edit、Theme、Windows 菜单的项从 C++ 挪到 Python，纹理板的 File、Setting 菜单也一样。依据是 `../developer_guide.md`「分工」第二条（#104）：菜单有哪些项是逻辑，归 Python；C++ 只提供通用函数。

## 已定决策

- 对用户不变：菜单的 id、文字、快捷键、勾选和可用状态、顺序都和现在一样。新旧对比里 `menus`、`textureMenus` 两个状态不应有任何差别。
- 一级 `../user-workflow.md` 第 18 行末句写的是「Draw、Arrow、Auto Mapping 三个菜单由脚本提供」，做完后会过时。改不改、怎么改，由用户定。

## 现状（main 19f9bc7）

- `backend/session/backendsession.cpp` 的 `buildMenusState`、`buildTextureMenusState` 内建以下菜单：
  - 主窗口：File（含 Import、Texture ▸ Setting）、Edit、Theme、Windows；
  - 纹理板：File、Setting。
- Python 用 `python_hooks.register_menu` 登记的菜单（Auto Mapping、Draw、Arrow、Settings、纹理板的 View）怎么排：
  - C++ 在初始化前后各收一次菜单名，按收到的顺序插在 Edit 和 Theme 之间；
  - 带 `place: "end"` 的排在 Windows 后面。
- `triggerMenuById` 认识每一个内建 id：
  - `file.*` 转给 Python（`file_menu.py`）；
  - `edit.undo/redo`、`theme.dark/light`、`windows.*`、`child.setting.*` 直接在 C++ 里做。
- 网页也拿 `windows.*` 当开关窗口的接口，都发 `menu.trigger windows.<名字>`：
  - 用户关掉独立面板窗口（`panelwindows.js`）；
  - Timeline 的关闭钮和小圆钮；
  - 把 Tools / Tool Options 面板拉出来。

## 设计

| 层 | 做什么 |
|---|---|
| Python `pyfile/app_menus.py`（新） | 声明主窗口的 File、Edit、Theme、Windows 和纹理板的 File、Setting：项、id、快捷键、勾选和可用状态（读 `ui.state` 的 `history`、`theme`、`windows`、`textureSettings`）。处理这些项的 `menu` 事件：File 项交给 `file_menu.run`；其余调通用方法 `history.undo/redo`、`theme.set`、`windows.setVisible`、`windows.showTextureView`、`texture.setChangeable`、`texture.setBackground`。接了就置 `message["handled"]` |
| Python `pyfile/python_hooks.py` | 菜单可带 `order`：数字小的在前，缺省 50，同值按登记先后。`menus_json` 按它排好，替掉 `place`。项可带 `id`，C++ 照用。子菜单可以引用另一个登记的菜单（`"menu"`、`"host"`），它的项用那个菜单的 id 和路由 |
| C++ | 菜单栏只按 `menus_json` 的顺序和内容建，不再收菜单名。带 `id` 的项记下它属于哪个菜单；触发时作为那个菜单的 `menu` 事件交给 Python，没有处理器置 `handled` 就报错。去掉内建的菜单和它们的 id 分支。新增上面四个通用方法，以及纹理板设置的 `textureSettings` 状态 |
| 网页 | 开关窗口改调 `windows.setVisible`，不再借 Windows 菜单的 id |

顺序：
- 主窗口：File 10、Edit 20，脚本菜单 50（Auto Mapping、Draw、Arrow，按登记先后），Theme 80、Windows 90、Settings 100；
- 纹理板：File 10、Setting 20、View 50。

主窗口 File ▸ Texture ▸ Setting 引用纹理板的 Setting 菜单。Setting 里引用纹理板上 Python 登记的其它菜单（现在是 View）：
- 子菜单的 id 仍是 `child.menu.<名字>`；
- 里面的项仍是 `script:child:<菜单>:<项>`。

## 风险

- Python 初始化前菜单栏是空的。网页连上时初始化已经做完，冒烟和新旧对比会看出来。
- 路由表要在菜单状态建过之后才有。触发时找不到，就先建一次再找。
- 引用子菜单可能绕成圈，要限深度。
- Windows 菜单的项来自 `windows` 状态，读它时会再进 Python（纹理板按钮）。不能在菜单的项里读 `menus` 本身。
- 新旧对比会有两类预期差别：
  - `textureSettings` 是新状态键，开关这些设置的步骤会多推它；
  - 交给 Python 的菜单项会多出 hook 记录。
  - 除此之外，`menus`、`textureMenus` 和各步的回复应当一字不差。

新旧对比（main 的后端对本分支的后端，497 步）：`menus`、`textureMenus` 两个状态、每一步的回复和画面都一字不差。差别只有三处：
- 启动日志多一行 `[OK] import app_menus`；
- 13 个触发内建菜单项的步骤多一条 Python 的 `menu` 事件，都已置 `handled`；
- `textureSettings` 这个新状态键出现在启动和 7 个纹理板设置的步骤里。

和计划不一样的地方：
- 纹理板的 Setting 菜单本来就在主窗口 File ▸ Texture 下面也有一份。现在后者用子菜单引用前者，两处的 id 和路由相同。
- 页面上 `menu.trigger` 的 `checked` 原样带进 `menu` 事件，不给就不带，Python 据此切换。黄金场景里不带 `checked` 的切换照旧能用。
- 没有菜单声明的 id（比如以前转给 Python 的 `file.nothing`）现在报 `Unknown menu id`，和别的未知 id 一样。
