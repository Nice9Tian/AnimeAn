# 多个页面同时连接一个后端

2026-11-13 开工。分支 `claude/sleepy-dhawan-752739`。

## 起因

用户在 Claude 的浏览器面板里打开了 AnimeAn 的网页界面，又在 Chrome 里打开同一个地址。后端同一时间只服务一个连接，Chrome 连上时把面板那一页断开了，之后 Chrome 里画的东西面板里看不到。

用户 2026-11-13 的要求（原话）：

> 我认为browser里面，和chorme打开的内容，应该是同一个画面。任意一端操作的结果，都会通过前端传输到后端，然后得到完全一致的结果。但是现在的表现是chrome画的，browser不同步。

## 目标

1. 同一个后端可以同时连着几个页面，后来的页面不挤掉先来的。
2. 每个页面看到的是同一份工程、同一个画面：任何一页的操作，所有页面都跟着变。
3. 只连一个页面时，行为和改动前相同。

不做：每个页面各自的缩放和平移；多人协作时的冲突合并；页面断线后的自动重连。

## 级别

- 一级不动。`architecture.md` 只说「界面只通过本地连接调用它」，没有规定连接数。
- 二级不加条目。发布形态是 Tauri 外壳，外壳只有一个主窗口页面，用户在外壳里看到的行为不变。
- 三级：`mechanism/backend_protocol.md` 里「同一时间只服务一个连接，第二个连接到来时断开旧的」这一条要改，另加「多个页面」一节；`mechanism/modules.md` 里 `WsServer` 的说明跟着改。

## 已定决策

下面几条是 Agent 定的，写在这里等用户过目。

| 问题 | 决定 | 理由 |
|---|---|---|
| 新页面连上时旧页面怎么办 | 都留着 | 用户的要求 |
| 调用的回复发给谁 | 只发给发起调用的那一页 | 各页的调用编号各自从 1 数起，发给别的页面会被当成它自己那次调用的结果 |
| 状态、画板帧、图片、场数据发给谁 | 所有页面 | 同一个画面 |
| 画板的尺寸听谁的 | 后端每块画板只有一个尺寸，听「操作页」的；其余页面把同一帧按比例缩放后显示，四周留边，指针坐标按同一比例换算回去 | 画板的洋葱皮和播放缓存都是按画板像素尺寸渲染的位图，一块画板没法同时有两个尺寸 |
| 换操作页时视图怎么办 | 画板中心对着的文档位置不动，缩放乘以两边面积比的平方根 | 缩放不变、钉在左上角时，侧边栏接手全屏窗口的画面会一下放大约 3 倍；按「接手方看到的完全不变」去算，窗口形状不同时来回交接会越切越小。面积比的平方根两边能看到的文档面积相同，来回交接的两个系数乘起来是 1 |
| 谁是操作页 | 第一个连上的页面；之后哪一页在画板上做完一次操作（按下到松开，或者滚轮缩放），哪一页就成为操作页；操作页断开时换成最近操作过的那一页 | 正在用的那一页应当按自己的窗口大小显示。只把鼠标移过去不算，免得路过另一个窗口时画面来回变 |
| 两页同时按着画板 | 先按下的那一页占着画板，直到它松开；这期间别的页面发来的指针事件丢弃 | 两条指针轨迹混进同一笔会画出乱线 |
| 占着画板的页面中途断开 | 后端替它补一次松开 | 否则那一笔收不了尾 |
| 新页面连上时画板怎么同步 | 所有页面一起从头来：后端忘掉发过的图片（先让旧页面释放），下一帧是完整帧 | 图片记账每块画板只有一份，要求所有页面手里的图片相同；连接是少见的事，重发一次的代价可以接受 |
| 收到确认才发下一帧，听谁的确认 | 任何一页确认了最新一帧就继续 | 一页卡住不该拖住其它页面 |
| 一页长时间不收数据 | 连着两个以上页面时，积压过多或长时间没有进展的页面会被断开；只连一个页面时不断 | 广播以后，卡住的页面会让后端的发送缓冲无限增长。只有一个页面时保持原有行为 |
| 场显示能力（`board.capabilities`） | 每页各报各的，所有报过的页面都支持才算支持 | 只要有一页画不了场，Python 就得走不用场的那条路 |
| 纹理板的归属（`texture.setHome`） | 每页各报各的，只有操作页的生效；换操作页时换成新操作页报的 | 归属跟着页面的布局走，两页布局可以不同 |

## 设计

### 连接层 `backend/net/wsserver.*`

- 每个连接一个编号（从 1 起，不复用），各有自己的收发缓冲和分片状态。
- 信号带上编号：`clientConnected(id)`、`clientDisconnected(id)`、`textReceived(id, data)`、`binaryReceived(id, data)`。
- `sendText(data)`、`sendBinary(data)` 发给所有连接；带编号的重载只发给那一个。
- 回调里可能断开任何连接，所以每次回调之后都按编号重新查找，不留指针。

### 会话层 `backend/session/backendsession.*`

- 每个页面一份记录：它报的画板尺寸、纹理板归属、场显示能力。
- 处理一条消息时记下是哪一页发来的，回复只发给它。
- 连上：只给新页面补发缓存的图片和全部状态；然后两块画板重新铺底（见上表）。
- 输入：按上表的规则决定收不收、要不要换操作页。`resize` 记在页面名下，操作页的才应用到画板。

### 画板 `backend/board/*`

- `RecordingDevice::forgetSentImages` 多一个参数：忘掉之前先逐个通知，让页面释放。

### 网页 `webui/`

- 一帧的尺寸和画板元素的尺寸差到 1 像素以上时，画板按比例缩放居中显示（`object-fit: contain`），动画叠层同样处理。
- 指针坐标换算成后端画板的坐标后再发。
- 上报的仍是页面自己的画板尺寸，后端在它成为操作页时采用。

## 施工顺序

4. 画板：图片忘掉时通知。
5. 网页：缩放显示、坐标换算、叠层。

8. 改机制文档，回填本文。

## 风险

| 风险 | 对策 |
|---|---|
| 连接层回调里连接被删，留着的指针失效 | 回调之后一律按编号重新查找 |
| 只连一个页面时行为变了 | 金标准对比要逐条相同；会话冒烟全过 |
| 外壳页面和普通浏览器页面连着同一个后端时，浏览器页面没有文件选择框，会立刻回答「取消」，把外壳那边的选择框流程取消掉 | 外壳的后端端口和令牌不对外，正常使用碰不到；写进机制文档的「限制」 |
| 镜像页面的画面是整张缩放的，放大时发虚 | 先接受；在那一页上操作一次它就成为操作页，按自己的尺寸显示 |

## 回填

2026-11-13 完成。

### 和计划的差别

- 加了「换操作页时视图怎么办」一条（见上表）：最早的实现换页时缩放不变、钉在左上角，算下来侧边栏接手全屏窗口的画面会放大约 3 倍。
- 拿着指针的页面又移动、却报告没有按键按着时（松开的消息丢了，或者在窗口外松开），指针随即放开，别的页面不用一直等它。
- 浏览器里的页面断开时弹框说明，要刷新重连（新文字进了 `zh-CN.json`、`ja.json`）。

### 审查

一个 Claude 子 Agent 对照代码审了整批改动，四条确认成立，都已修好并加了测试：

| 问题 | 怎么修 | 测试 |
|---|---|---|
| 交接时纹理板换了位置（一页放中央、一页放子控件框），回到原位置时视图又被按面积比缩放一次：缩放从 1 变成 4（审查附了复现脚本，跑出来一样） | 纹理板换了位置时只改尺寸，用那个位置上次的视图 | `multi_page.mjs` 8a |
| 操作页断开时立刻交接：别的页面正按着笔时画板也会换尺寸；而且这一步可能发生在一次群发的半途，交接时发出的光标图片会插进别的图片的头和数据之间 | 交接挪到下一轮事件循环，有页面按着指针时等它松开 | 11a |
| 被丢弃的拖动中间滚一下滚轮（滚轮消息不带按键），后面的移动和松开就漏到画板上；中途按第二个键也一样 | 只有指针类消息、并且报告没有键按着，或者是没有别的键按着的新按下，才结束丢弃 | 6b |
| 不是操作页的页面改了窗口大小，没有新帧到达时画面按元素拉伸，和指针换算对不上 | 画板元素尺寸变了也重新判断要不要按比例显示 | 无单测（`app.js` 的画板挂载没有单测），真实页面实测里改过窗口大小 |

另有三条记录在案、不改：只连一个页面时笔按着断开，后端补一次松开（比以前留着不收尾好，写进了机制页）；Python 里没有地方调 `texture.setHome`，审查担心的「脚本设的位置被换回去」碰不到；一页按着指针时别的页面的焦点消息也丢掉，画板的焦点只有一份，几页同时用时本来说不清属于谁。

### 须知

- 测试里两页的消息之间没有先后，要用一次往返调用（未知方法也行）确认一页之前发的都处理完了，再看结果；一次调用会放出一帧等着的画面，比对前要等各页收齐。
- 笔还按着的时候调 `python.run` 会把正在画的那一笔结束掉，单页时也一样，测试里别这么做。
