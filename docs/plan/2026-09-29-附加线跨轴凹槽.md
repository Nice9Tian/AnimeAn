# 附加线跨越正交轴处的凹槽（2026-09-29）

状态：**已修（2026-09-30，提交 e811348）。** 按 `2026-09-30-附加线跨轴放行施工计划.md` 施工：被跨过的半条轴放开沿轴分量，轴线不变形；同日先补进文档的"跨过轴时不生效"措辞已全部换成新语义。施工时的补充（恰落在轴上的站位照样算跨过；被跨过的半条轴通向的版心边被画出去时不放行）和实测见施工计划文末回填。下文是定位时的原始记录，数字是修之前的。

## 现象

用户 2026-09-29 测试后提交的样本：`../../tests/fixtures/additional_line_axis_notch.anproj`。纹理板上一条近水平的附加线，在 Third 空间里沿 ℓ_v 方向延伸（属 V 族），跨过 H 轴（ℓ_v = 0）。跨轴处，附加线本应带来的位移被压成零，图案和参考网格在那里出现一道凹槽。用户怀疑 V 轴也一样：按机制看是对称的，H 族线跨 V 轴会得到同样的凹槽（未另做样本）。

样本里的两条轴：文件里叫 `h_center_line` 的那条在纹理板上画成近竖直（弦向 83°），`v_center_line` 近水平（−3°）。附加线弦向 −6°，和 V 轴几乎平行、跨过 H 轴。用户口中的"水平轴线 / 垂直轴线"是按屏幕上的样子说的，对应文件里的 V / H。

## 复现

```powershell
py tests\diag_additional_axis_notch.py
```

离线加载样本的单元资产，建两个映射器（带 / 不带附加线），量「带附加线 − 不带附加线」的位移。跨轴的图案笔画（样本里的 stroke 1）在跨轴处的位移，主画板像素：

| 位置（Third ℓ_v） | 位移 |
|---|---|
| 轴一侧 ≈ +39 | 8.6 |
| ≈ +16 | 4.9 |
| ≈ +10 | 1.6 |
| 钉扎带内（ℓ_v 在 ±6 以内） | 0.00 |
| ≈ −11 | 2.1 |
| ≈ −19 | 3.8 |
| 另一侧 ≈ −36 | 4.8 |

过跨轴点的网格等参线（ℓ_h = 165.3）上同样：两肩 4.4–4.7 与 7.0–8.3，轴带 |ℓ_v| ≤ 5 精确为 0，**凹槽深约 6 px**（两肩均值 6.2），到 |ℓ_v| ≈ 25 才基本恢复。流场本身在 Third 空间的位移是 6.0 / 0 / 10.6 px（两肩 / 轴上）。网格格宽 10.9 Third px（窗 96 格）。

**凹槽只是最显眼的症状。** 这条线在跨轴处的请求是沿 H 轴滑 47 Third px（主画板上画的线过 H 轴的位置在 ℓ_h = 118，纹理板上在 165）。现行代码在跨轴处兑现 0，全线各站残差均值 31.8 px、最大 47.7 px：整条线的请求被吞掉八成左右，两肩那 5–8 px 只是漏出来的零头。

排除项：

- 去掉附加线后同一条笔画没有凹槽，基础映射（只有 H/V 轴）无关。
- 保存的输出里主画板 (241, 282) 处有一个 171° 的折返，与凹槽无关：对应的纹理笔画自己在 y ≈ 316.5 处折返了一次（x 434 → 425 → 434），映射在那里是忠实的（雅可比行列式为正）。那是画的时候手回了一下，不是缺陷。

## 原因

`pyfile/auto_mapping.py` 的 `_FlowFieldWarp._build`：

1. **轴带全分量硬钉。** `axis_pinned` 选出离 ℓ_v = 0 与 ℓ_h = 0 一格以内的网格行 / 列，然后 `pinned_x = pinned_y = axis_pinned`：两条轴上 U 的两个分量都被钉成恒等（Dirichlet）。
2. **正交轴旁的 4 格缓冲。** `o_t = clip(|o_pt| / (4·o_cell))` 的 smoothstep 乘进每条线的权重，V 族线在 H 轴两侧各约 4 格（≈ 44 Third px）内声音渐弱到零。
3. **这条线偏偏要把位移带过轴。** 配对在跨轴处的请求几乎全是沿 ℓ_h 方向的（≈ −47，切于 H 轴），法向只有 ≈ +6。钉扎带把切向也钉成 0，线自己的积分（两端重合、中间 −47）和轴带矛盾，求解器折中的结果就是整条线大部分不兑现，轴两侧各留一个肩。

分族本身没有错：`family_of` 按 Third 空间的行程判族，这条线 ℓ_v 行程 358、ℓ_h 行程 17，判为 V 族，权重从它平行的 V 轴（ℓ_h = 0）起坡到线上——"向平行轴衰减"已经是现状，平行轴那边没有凹槽。问题全在**被跨过的那条轴**（H 轴）上。设计文档说"V 族线跨 H 轴时声音不被 H 静音（正交族互不干扰）"，但钉扎是全分量的、缓冲又是按格数的，实际把线在轴带内静音了。`../auto_mapping/flow_field_warp.md` 第 6 节第 4 条把"正交轴旁 4 格是钉扎与谐波回弹的地盘（约 1 px）"列为已知取舍；本样本里这个取舍的代价是整条线。`tests/t_flowfield.py` 里检查的是正交轴旁的倾斜是否保留，没有断言位移跨轴连续，也没有量过跨轴线的残差，所以没有测试拦住它。

## 修法实验（2026-09-30，草稿副本，仓库未动）

在 scratchpad 里复制 `pyfile/auto_mapping.py`，只改钉扎和缓冲两处，用环境变量切换，跑样本和六个附加线回归脚本（`t_flowfield`、`t_compose`、`t_additional`、`t_twofix`、`t_third_invalidate`、`t_removal`；现行代码全绿作对照）。

**试法 A：全局分量式钉扎**（H 轴行只钉 ℓ_v，V 轴列只钉 ℓ_h，和外轮廓一样）。样本修好（残差均值 6.6，无折叠），但 `t_flowfield` 第 3 例、`t_additional` 第 2 / 8 例、`t_twofix` 第 5 例失败：三个夹具里的线都**没有跨轴**，只是影响带够到了轴。它们的积分常数一直是靠被跨过那条轴的切向钉扎定住的，全局放开后整条影响带"浮动"（轴上探针漂 3–53 px）。**否决。**

**试法 B：只在被跨过的轴上放开切向。** 规则：

- 轴的法向分量永远钉死（轴这条曲线不变形），原点两个分量都钉死；
- 某条附加线的 child 站位跨过某条轴（正交坐标变号）时，那条轴在**线所在的半边**放开切向分量（沿轴滑动），跨越点的地面按画的位置沿轴滑过去；
- 没有线跨过的轴维持现状（两个分量都钉），影响带不会浮动；
- 正交轴旁的 4 格缓冲不动。

草稿补丁（`_FlowFieldWarp._build` 里 `pinned_x = pinned_y = axis_pinned.copy()` 那两行换成）：

```python
pinned_x = axis_pinned.copy()
pinned_y = axis_pinned.copy()
on_v = np.abs(gx) <= du * 0.999          # V 轴列（ℓ_h = 0）
on_h = np.abs(gy) <= dv * 0.999          # H 轴行（ℓ_v = 0）
rel_h = np.zeros(gx.shape[0], dtype=bool)   # H 轴上放开 ℓ_h 的节点
rel_v = np.zeros(gy.shape[0], dtype=bool)   # V 轴上放开 ℓ_v 的节点
for ln in active:
    pts = ln["child"]
    for a, b in zip(pts[:-1], pts[1:]):
        if a[1] * b[1] < 0.0:                 # 跨 H 轴
            xc = a[0] + (b[0] - a[0]) * (-a[1]) / (b[1] - a[1])
            if xc != 0.0:
                rel_h |= (np.sign(gx) == np.sign(xc))
        if a[0] * b[0] < 0.0:                 # 跨 V 轴
            yc = a[1] + (b[1] - a[1]) * (-a[0]) / (b[0] - a[0])
            if yc != 0.0:
                rel_v |= (np.sign(gy) == np.sign(yc))
pinned_x[np.ix_(rel_h, on_h)] = False     # 被跨过的 H 轴：这半边可沿轴滑
pinned_y[np.ix_(on_v, rel_v)] = False     # 被跨过的 V 轴：这半边可沿轴滑
pinned_x[on_v, :] = True                  # V 轴保形（ℓ_h）
pinned_y[:, on_h] = True                  # H 轴保形（ℓ_v）
```

样本结果（主画板 px）：

| | 现行 | 试法 B |
|---|---|---|
| 跨轴处凹槽 | 6.1 | 无（剖面 31 → 34 → 38，平滑） |
| 线各站残差 均值 / 最大 | 31.8 / 47.7 | 6.6 / 15.1 |
| 跨轴处兑现 | 0 / 47.7 | 41.3 / 47.7 |
| 流场折叠格数 | 4 / 14641（跨轴处被压出来的） | 0 |
| H 轴法向漂移 | 3e-15 | 3e-15 |
| H 轴切向滑动 | 0 | 原点 0 → 跨越点 47 → 窗边 0 |
| V 轴（没被跨） | 0 | 0 |

回归：六个脚本里只有 `t_flowfield` 两处"轴上探针总位移 < 0.01"读到了滑动——第 5 例（弓形线跨 V 轴、伙伴是弦）31 px，就是弓顶顺着 V 轴滑向弦；第 21 例（斜线跨自己的 H 轴）0.97 px。两例其余断言（跨轴旁的流向 ±19°、平滑交接、无折叠、可逆）都过。其他四个脚本和 `t_flowfield` 另外 19 例全部原样通过。

**缓冲宽度**另试过 1 格和 0 格：样本残差从 6.6 降到 3.5，但 0 格让 `t_flowfield` 第 12 例"诚实折叠"的夹具不再折叠。收益小、牵动多，**不改缓冲**。

## 拍板的问题（2026-09-30 已拍板：改）

一句话：**被附加线跨过的轴，允许地面在跨越点沿轴滑动（轴的形状照旧不变）；没被跨过的轴一切照旧。** 这改写 `../auto_mapping/flow_field_warp.md` 第 3 节"轴线神圣"的措辞（"轴上恒等" → "轴不变形；被跨过处可沿轴滑动"）和第 6 节第 4 条的取舍说明。

拍板后的施工：

1. `pyfile/auto_mapping.py` 按试法 B 改钉扎，并同步 `dist`；
2. `tests/t_flowfield.py` 第 5、21 例的"总位移 < 0.01"改为"法向 < 0.01 且切向等于画的请求"，新增一例"V 族线跨 H 轴"：跨轴处位移连续（凹槽 < 0.5 px）、线残差 < 10 px、无折叠；样本 `tests/fixtures/additional_line_axis_notch.anproj` 作为回归夹具；
3. 一级文档两处措辞（用户批准后由用户或授权改）；`../mechanism/` 若有提到轴线钉扎的地方同步；
4. 全量 `py -m unittest discover -s tests`，用样本目测参考网格。

## 不做

- 不改基础映射（H/V 轴的 Coons 复合），它与此无关。
- 不改附加线的族判定和关键帧插值：分族已经能区分线被哪条轴截断（跨过的那条就是正交轴），缺的只是被截断的轴放行。
- 不全局放开切向（试法 A）。
