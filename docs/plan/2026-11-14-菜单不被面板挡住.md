# 菜单不被面板挡住

用户 2026-11-14 让在真机测试的会话里直接做。真机上，浮出的面板窗口会盖住主窗口里打开的菜单：Layers 面板浮在左上角时，Windows 菜单下半截和 File 菜单的一部分都在它后面，看不见也点不到。

## 现状（main 9e8aa8a）

- 菜单都画在打开它的那一页里：
  - 菜单栏的菜单（`webui/src/ui/panels.js` 的 `createMenuBar`）；
  - 图层右键菜单；
  - 后端发来的 `contextMenu`。
- 三者都走同一个 `popupMenu(items, x, y, onTrigger)`，子菜单嵌在同一个 `.qmenu` 里，在别处按一下就关。
- 浮出的面板是主窗口所属的独立窗口（`open_panel_window`），Windows 规定所属窗口永远在所有者之上，所以画在主窗口页里的东西都会被它们盖住。

## 设计

菜单还画在原来那一页里，样子和行为都不变。外壳给一个通用函数：一页打开菜单时，把菜单占的矩形报给外壳，外壳给叠在这一页窗口之上、又和这些矩形相交的 AnimeAn 窗口设一个挖掉这些矩形的窗口区域（`SetWindowRgn`）。于是菜单从洞里露出来，鼠标在洞里也落到菜单所在的窗口上。菜单关了就报一个空列表，外壳把区域还原。

| 层 | 做什么 |
|---|---|
| 外壳 `set_menu_area(label, rects)` | rects 是那一页的客户区坐标（逻辑像素）。换算成屏幕坐标，找出 z 序在这个窗口之上的本程序窗口，相交的就挖洞，其余的还原。只记自己挖过洞的窗口，还原时只动它们 |
| 网页 `panels.js` | `popupMenu` 打开、子菜单展开或收起、菜单关闭时，量出所有 `.qmenu` 的矩形报出去（同一帧只报一次，没变不报）。窗口失去焦点（点了别的窗口或别的程序）时关菜单，免得洞留在原处 |
| 网页 `app.js` | 有外壳时把报出的矩形连同本窗口的 label 交给 `set_menu_area` |

不选的做法：
- 菜单单独开窗口：要一直预热一页、量级联子菜单的大小、处理焦点，开菜单也慢。
- 用系统原生菜单：样子会变。
- 开菜单时把面板藏起来或挪到后面：面板会闪，所属窗口也挪不到所有者后面。

## 施工顺序

1. 计划（本文）。
2. 外壳：`set_menu_area`、矩形相交的纯函数和 `cargo test`、`Cargo.toml` 加 `Win32_Graphics_Gdi`。
3. 网页：`panels.js` 报矩形、失焦关菜单；`app.js` 接到外壳；`npm test`、`tsc`。
4. 三级文档：`../mechanism/windows_theme.md`、`../mechanism/backend_protocol.md`（外壳命令一节如有）。
5. 打包（后端用 main 的构建，C++ 和 Python 不动），在真机上用 computer-use 实测：面板盖着时打开 File、Windows 菜单，菜单完整可点；关菜单后面板复原。
6. 审查、合入 main、重建 dist。

## 风险

- WebView2 的内容是否听窗口区域的裁剪：先在真机上试，不行再换做法。
- 菜单开着时面板窗口被挪动：洞留在面板的旧位置。点面板会让主窗口失焦并关菜单，拖动面板也要先按下它，所以不会出现。
- 洞会去掉 Windows 11 窗口的圆角和阴影，只在菜单开着的那一会儿。

## 回填

2026-11-14 按原设计做完，没有换做法。

- 外壳：`src-tauri/src/lib.rs` 的 `set_menu_area` 和纯函数 `menu_holes`（矩形和窗口求交，换成窗口内坐标，测试 `test_menu_holes`）；`Cargo.toml` 的 windows-sys 加 `Win32_Graphics_Gdi`。外壳只还原自己挖过洞的窗口（第一版记一个 label 集合，审查后改成记每个洞是谁挖的）。
- 网页：`webui/src/ui/panels.js` 的 `onMenuArea` 和 `reportMenuArea`（微任务里量一次，JSON 没变不报），`blur` 关菜单；`webui/src/ui/app.js` 在 `createChrome` 里接到外壳。
- 测试（第一版）：`cargo test` 12 个通过；网页 `npm test` 171 个通过、1 个跳过，新增「打开的菜单把占的矩形报给外壳」（打开、子菜单展开收起、点项关闭各报一次，没变不报），测试替身的 `querySelectorAll` 学会了 `:scope > `；`tsc` 通过。
- 真机实测（computer-use，打包的本分支，Layers 面板浮在左上角盖住菜单区）：
  - File 菜单整个露出来，Import ▸ 子菜单也露出来，鼠标在洞里能悬停高亮子菜单项；
  - Windows 菜单右半截压在面板上，点洞里的 History 打开了 History 面板；
  - 菜单开着时面板窗口有区域（`GetWindowRgn` 读到 COMPLEX），主窗口没有；菜单关后、点面板失焦关菜单后、按住标题栏拖主窗口后，所有窗口都没有区域；
  - WebView2 的内容听窗口区域裁剪，风险第一条不成立。
- 审查（Claude 子 Agent 提了七条，逐条核对后都改了，第四、第七条一起改）：
  - 失焦时菜单还在等 `menu.refresh` 的回复，回复到了照样打开，在没人用的窗口里挖洞：失焦时一律作废等着的菜单，并且到这一页被按下或拿回焦点前不开菜单（后端的 `contextMenu` 没有 `askForMenu`，也靠这一条）。
  - 伸出主窗口的子菜单看不见，却会在主窗口外的面板上挖出透明的洞：外壳先把矩形裁到菜单所在窗口的客户区（纯函数 `menu_rects`，测试 `test_menu_rects`）。
  - 菜单开着、窗口不失焦却挪了位置（Win+方向键）或改了大小，洞留在旧处：移动（`onMoved`）和改大小（`resize`）都关菜单。
  - 外壳只有一张「谁有洞」的表，主窗口报空列表会还原面板菜单挖的洞；带着菜单的窗口关掉，洞留下：改记每个洞是哪个窗口挖的，只还原自己挖的，窗口销毁时还原它挖的。
  - `SetWindowRgn` 失败时区域还归调用方却没释放、名字照样记下；`GW_HWNDPREV` 一路往上走，z 序变了可能走不完：失败时释放、不记，z 序改用 `EnumWindows`。
  - 外壳用自己的缩放比换算网页的逻辑像素，网页缩放和它不一致时洞会偏：网页直接报设备像素。
- 第二轮审查（同时审了模态点面板和两个实例串台的修复，见 `../long_time_work/2026-11-03-对话框窗口.md`），逐条核对后改了四条：
  - 不给名字的 `RelayClient` 还在旧的 `animean.relay` 上，没有主窗口页在听：默认改为本页的运行名。
  - 失焦时被拒的菜单仍把标题标成打开，下一次点标题被当成「按下关菜单」：只有真打开了才标。
  - 页面重载或崩溃时开着菜单，窗口没销毁，洞留下：页面加载时先报一次空列表。
  - `focus_modal` 可能挑中选择框的文件名建议列表或提示框：跳过置顶、工具窗口和不能激活的辅助弹窗（`test_modal_target` 加了这一种）。
  - 审查另提到主窗口页带着对话框重载时对话框 30 秒后报错关掉：main 上原有，打包版不能重载，没改。
- 合入前又测了一轮：`cargo test` 14 个、网页 176 个（175 过、1 跳过）、`tsc` 通过。
- 须知：菜单开着时点另一个菜单标题，鼠标一移进去就换成那个菜单（等 `menu.refresh` 回来），接着的按下落在已经开着的标题上，会把它关掉。这是 main 上原有的行为，不是本次改的；computer-use 的点击先把鼠标瞬移过去再按，看上去像「点了没开」，实测时别当成洞的问题。
