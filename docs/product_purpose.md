# 产品目的（product_purpose）

AnimeAn 是给动画人的二维线稿动画工具（Windows 桌面），核心功能是 Auto Mapping：把纹理板上的图案沿轴线贴到每一帧的线稿上，折到背面的部分自然消失并留下折痕。主画板逐帧画线稿，纹理板画图案（可以是多种纹理），在纹理和主画板上各画一对 H/V 轴线，图案就沿轴线的弯曲被"贴"上去。它要解决两件事：逐帧动画里，线稿上的图案（尤其服装花纹）怎样跟着形体弯曲、遮挡、并逐帧跟随；一个绘图工具怎样让算法在 Python 里随时改写而不重新编译。

本文和 `user-workflow.md`（含 `tools_user_workflow/` 每个工具一页）、`architecture.md`、`developer_guide.md` 一起是一级语义。**Auto Mapping 是本软件的核心，它的全部文档（算法规格、各条管线、Auto-Mapping 单元）与本文同级，放在 `auto_mapping/`。** 本文只说目的、承诺和边界；用户怎么用见 `user-workflow.md`，怎么做到见 `architecture.md`。

> 草稿状态：2026-09-28 由现有文档、README、代码文件头注释整理，同日按用户多轮反馈修订（分级、多纹理、发布计划、导入承诺、动画软件定位）；等用户对一级整体拍板。

## 要解决什么

- **图案跟着形体走，也跟着帧走。** 手绘线稿是二维的，画的却是三维的东西，而且一帧一帧在动。在纹理板上把图案画平，在主画板上用两条弯曲的轴线说明"这块面怎么弯"，图案就沿轴线弧长重建到线稿上：直轴线下是精确仿射，弯轴线下跟着弯。动画人不该逐帧手画花纹：轴线怎么动，花纹就怎么跟。
- **折叠就是遮挡。** 轴线弯到自相折叠时，纹理上的一个点对应主画板上两处（一对多）。AnimeAn 不糊合，而是在折缝处切断拓扑：正面、背面各成一层，折缝画成虚线标注，背面可以染衬里色或隐藏。用二维的拓扑裁断伪造三维的遮挡。
- **细化引导。** 除 H/V 轴线外，用户可以追加引导线，画下的线就是想要的等参线（测地线），纹理的流向被它牵引；可以放一条视平线告诉算法哪一端远；可以把 Auto Mapping 的结果反推成三维浮雕看一眼。
- **矢量可编辑。** 每一笔在抬笔时拟合成线段加三次贝塞尔的路径，之后能选、能拖锚点、能连接、能变形、能推开重叠线；栅格只作参考。
- **工具在 Python 里生长。** C++ 只留通用机制（渲染、手势、模型、绑定），工具的含义全部在 Python 脚本：实验性的算法、随功能扩展而变化的逻辑都在这里，改工具不重新编译。

## 谁在用

现在是作者一人开发、自用，**有面向其他用户发布的计划**（用户 2026-09-28 确认）。目标用户是**动画人**。发布形态暂定就是现在这个打包的压缩包：`dist\AnimeAn\` 文件夹压成一个包，解开即用，不做安装器。Git 仓库 `Nice9Tian/AnimeAn`。

功能取舍现阶段以作者自己的线稿工作流为准，但要为发布留余地：不把只在作者这台机器上成立的假设写进产品；用户看得到的行为要能向别的动画人解释；离线自足（承诺 10）是发布的前提之一。

## 承诺

改了下面任何一条，产品就不再是这个产品，改之前先改本文。

1. **一个主画板、多种纹理。** 主画板（Drawing）只有一个；纹理板（Texture）承载多种纹理，以分页管理，每页一个纹理、各自独立。在纹理和主画板上各画一对 H/V 轴线，图案就从那页纹理映射到主画板；多种纹理都能映射到同一块主画板上。用哪一页纹理在 Auto Mapping 工具的选项里选：选项块里有一个「映射纹理」下拉，点开列出各个纹理页；选中一个 Auto-Mapping 图层时选项块自动显示，在那里改这个单元的目标纹理。一个单元只映射一页纹理，多种纹理靠多个单元。这是软件的核心，其余工具围绕它。参考架除了手画一对 H/V 轴线，将来还有**轮廓模式**（Outline Mode）：在纹理页上用一个封闭轮廓把纹理围住，在主画板上只画这个轮廓变形后的样子（任意封闭轮廓，不限四边），框内的一对轴线和其他约束线由 Auto Mapping 自动生成；轮廓是多边形时边与边的对应要有专门算法。算法和交互都还没定，是待办。（分页栏与「映射纹理」下拉是规划中的功能，现有版本只有一个纹理；现有 / 规划的标记见 `product_features.md`。）
2. **只有一种 Auto Mapping。** 现行算法是平移扫掠（Coons 退化形）的纯分级复合 Child→Third→Main，无残差项；两块板画同一组轴线时 Auto Mapping 恒等（原图不变）。被淘汰的脊柱旋转算法与 Fukusato MLS 工作流只作归档，不再进软件。算法的规格、性质、阈值都在 `auto_mapping/`，和本文一样只有用户能改。
3. **折叠处裁断，不糊合。** 一对多的地方切断笔画、丢掉不可达段，正面 / 背面 / 折痕各成一层；用户看到的是图案绕到了背面。
4. **Auto-Mapping 单元是配置，不是画出来的层。** 一个 Auto-Mapping 图层是一个单元，拥有两块板的轴线、Mapping Area、附加线、锚点和生成选项；输出随时能从配置重生成，焦点进入单元就显示它的引导，改了引导就地重跑。
5. **矢量为本。** 笔画是拟合后的贝塞尔路径，锚点可编辑；填充是有边界的区域；栅格只作导入的参考层。
6. **逐帧动画是主线。** 帧、保持帧、洋葱皮、播放是一级承诺，骨架是 xsheet（帧、图层、资产、单元格）；一页纹理通常只有一帧。Auto Mapping 要能跟着每一帧走：单元的输出落在每一帧的线稿上（规划：单元的主画板轴线可逐帧调整，现有版本一个单元的轴线在所有帧上相同）。
7. **一切可撤销。** 撤销是整份模型的快照，任何来源（包括脚本）的改动都能退回，主画板与纹理按全局时间顺序撤销。
8. **工程文件保存完整工作区。** `.anproj` 同时保存主画板、全部纹理和脚本状态（Auto-Mapping 单元的配置、引导线、调色板等）；`.textureview` 单独保存一页纹理以便跨工程复用。
9. **C++ 通用，Python 具体。** 属性名、颜色、工具流程、数据结构在 `pyfile/*.py`；C++ 里出现"if 工具 == 某某"就是放错了地方。
10. **离线自足。** 内置完整的 Python 运行时，依赖的 wheel 随包分发，首次使用时自装；没有网络也能运行、能补齐依赖。
11. **别的软件画的线稿能导进来。** OpenToonz 的场景与矢量 level（`.tnz` / `.pli`）和 Clip Studio Paint 的 `.clip` 矢量笔画都能导入主画板或纹理板。这是承诺；现有实现还没做过完整测试，在 `product_features.md` 里标为待办。

## 不做什么

- **不重造栅格绘画软件。** 栅格只导入为参考层，不提供画笔式栅格绘制。
- **不做三维建模。** To 3D 是从 Auto Mapping 的雅可比反推的浮雕查看器（离线 HTML），用来核对 Auto Mapping，不是建模器、不是渲染器。
- **不做通用动画套件。** 不做音频、合成、特效、视频输出；OpenToonz 只读它的线条（`.tnz` / `.pli`），不解栅格 `.tlv`，也不写回。
- **不在 C++ 里写工具语义。** C++ 只加基础函数；一个功能会怎么变，由 Python 决定。
- **不做多用户、不上云、不做安装器。** 单机运行；发布就是自包含文件夹打成的压缩包，解开即用。
- **不保留被淘汰的算法路径。** 脊柱旋转（AM1）、链式复合的附加线、Fukusato MLS 都已移除，只留归档说明供查阅。

## 怎么判断做对了

- 在纹理板画一张图案，在纹理和主画板上各画弯曲的轴线，点 Auto Mapping：图案沿轴线弯曲，折到背面的部分消失，折缝处有虚线折痕；把两边的轴线画成一样，Auto Mapping 的结果与原图一致。
- 纹理板上放几页不同的纹理，「映射纹理」下拉选哪一页，主画板上就贴哪一页；几页纹理靠几个单元各自映射到同一块主画板上（规划）。
- 画几帧线稿，花纹在每一帧上都贴在形体上，洋葱皮里能看到前后帧的花纹，播放时花纹不跳（轴线逐帧调整是规划）。
- 拖动主画板的轴线或改一个生成选项，单元的输出就地更新，不多出一层，旧层不残留。
- 改一个工具的行为只改 `pyfile/` 下的脚本，同步脚本后重启即生效，不重新编译。
- 任意一串操作按 Ctrl+Z 逐步退回，包括脚本产生的改动；历史窗里点任意一行能跳到那个状态。
- 保存再打开，主画板、各页纹理、Auto-Mapping 单元、附加线、调色板都在原处。
- 把 `dist\AnimeAn\` 复制到一台离线的新机器上直接能运行；首次用到需要 numpy 或三角化库的功能时自动从随包的 wheel 安装。
